# 任务启动清单（阶段二：多API兼容性改造）

## 主线目标
- 在不破坏现有 ETL 调用路径的前提下，系统化解决“原有代码中多API兼容性不一致”问题。
- 建立可持续的兼容性治理机制：先盘点、再分批改造、再回归验收。

## 交付标准
- 产出完整 API 兼容性盘点清单（接口、来源、方法、路径、风险、优先级）。
- 在服务内提供兼容性路由元数据输出接口，支持联调与验收对齐。
- 形成阶段改造计划文档，明确每批次改造范围与验收方式。

## 验收标准
- 可通过接口和文档快速回答：当前有哪些 API、由谁负责、兼容风险是什么。
- 至少覆盖当前主服务 `app/main.py` 中全部对外路由。
- 改造不影响现有生产调用路径和返回语义。

## 团队分工
- 执行角色（后端兼容改造）：小C负责盘点自动化、路由元数据输出、改造计划落地。
- 独立审查角色（质量复核）：小C按清单逐项复核覆盖率与风险标注完整性。

## 并行策略
- 并行1：代码静态扫描提取路由信息。
- 并行2：人工补齐外部依赖来源与风险标签。
- 并行3：生成文档与服务内查询能力，形成统一事实源。
