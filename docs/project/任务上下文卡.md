# 任务上下文卡（阶段二：历史方案复盘与兼容性优化）

## 背景
- 第一阶段已完成：ETL 通过中间件访问领星 OpenAPI，鉴权与签名已收敛到服务端。
- 当前进入第二阶段：历史代码中多个 API（领星 Web/IHR/K3/Mongo 视图）返回结构、容错策略、排障手段不一致。

## 当前痛点
- 同一系统内接口返回格式不统一，调用方适配成本高。
- 历史接口文档与运行事实不一致，联调时经常“靠猜”。
- 兼容性风险没有统一台账，容易修一个坏一个。

## 目标
- 形成全量 API 兼容性盘点（接口、方法、路径、来源、风险）。
- 在服务层提供兼容性元数据查询能力，便于联调/验收。
- 提供“可选兼容响应封装”能力，在不破坏旧调用的前提下，支持新调用方统一协议。

## 非目标
- 本批次不重构所有业务逻辑，不一次性改完全部接口实现。
- 不改变默认返回行为（避免影响线上已有 ETL 配置）。

## 风险
- 直接强制统一返回格式会影响历史调用方。
- 外部 API（领星/IHR/K3）本身存在限频/偶发抖动，需与兼容策略分层处理。

## 本批输出
- 兼容性盘点脚本与盘点文档。
- 服务接口：兼容性路由清单查询。
- 响应兼容封装（显式开关，默认关闭）。
